### 3.2 Intrusion Kill Chain <br> (Aiemmasta [raportista](https://github.com/SamiYli/Tunkeutumistestaus/blob/main/h1.md) )
[Hutchins et al 2011: Intelligence-Driven Computer Network Defense Informed by Analysis of Adversary Campaigns and Intrusion Kill Chains: 3.2 Intrusion Kill Chain](https://lockheedmartin.com/content/dam/lockheed-martin/rms/documents/cyber/LM-White-Paper-Intel-Driven-Defense.pdf)

Kyber tappoketju on systemaattinen maalittamisen ja hyökkäämisen prosessi.
Seitsemän tappoketjun vaihetta:
- Reconnaissance, etsitään kohteita ja haavoittuvuuksia.
- Weaponization, hyödynnetään haavoittuvuutta ja/tai luodaan haittaohjelma.
- Delivery, saatetaan haittaohjelma kohteeseen.
- Exploitation, haittaohjelma alkaa toimia kohteessa.
- Installation, ladataan etäkäyttö työkalu kohteeseen tai luodaan takaportti.
- Command and Control, haittaohjelma ja hyökkääjä muodostavat yhteyden.
- Actions on Objectives, hyökkääjä tekee rikoksiaan kohteessa ja/tai käyttää sitä alustana hyökätä muualle samassa verkossa.

Aktiivinen tiedustelu: Porttien skannaus eli avoimien porttien etsiminen, web-sovelluksien tutkailu, haavoittuvuuksien etsiminen.

- MASSCAN, nopea porttiskanneri.
- UDP-proto-scanner, UDP protokolla skanneri.
- EyeWitness, web-sovelluksien tutkailu.

Olen läpäissyt aiemmin keväällä muutaman HackTheBox koneen, joista on valmista raporttia luettavissa (https://github.com/SamiYli/Tunkeutumistestaus/blob/main/h1.md).

### CAP

![Cap](imagesh1/Cap.PNG)

Yhdistin OpenVPN:llä HTB harjoituskoneelle. HTB:n sivulla löytyy ohjeet VPN:llä yhdistämiseen, mutta ne eivät minulla aina ole toimineet.

Käytin seuraavaa tapaa: 
- Latasin HTB:n sivulta .ovpn tiedoston.
- Avasin advanced network configuration ja lisäsin uuden VPN konffin alakulmasta plus nappia painaen.
- Valitsin "Import a saved VPN configuration" listan pohjalta. Tähän tottakai valitsin lataamani .ovpn tiedoston.
- Sitten VPN päälle oikeasta yläkulmasta verkkoportin takaa.

Teron [läksy sivulta](https://terokarvinen.com/tunkeutumistestaus/#h1-kybertappoketju) hyvä vinkki VPN testaukseen:
Pingaa google, kun VPN päällä. Ei pitäisi onnistua.

#### Tutkitaan avoimia portteja
Ensiksi minua kiinnostaa avoimet portit. Siispä nmap aukinaisista porteista:
```
nmap -F -T5 <ip-osoite>
```
nmap vivut: (https://nmap.org/book/man-briefoptions.html)<br>
Skannaa ensimmäiset 100 yleisintä porttia parametrillä:
```
-F
```
Otetaan nopeampi skannaus:
```
-T5
```

![nmap](imagesh1/nmapCAP.PNG)

Katsokaas nyt! FTP, SSH ja HTTP auki. Näistä voidaan alkaa jo innostua. Vastaus ensimmäisessä taskissa on 3. <br>

FTP on tiedostojen siirtoon käytetty salaamaton protokolla. SSH on komentojen ajamiseen etäkoneilla ja HTTP on perus websivujen viestitys protokolla. HTTP portti avoimena antaa idean, että ehkä koneella pyörii webpalvelin.

Päätin katsoa selaimella pääsenkö käsiksi web palveluun, joka pyörii portissa 80.

![web](imagesh1/website.PNG)

Security dashboard! Melkoista settiä.

Task 2. vinkki oli: "Run a scan and look at the URL of the page you are redirected to. This part is the same every time." <br>
Tämä antaa ajatuksen katsoa mitä tapahtuu Security Snapshot (5 second PCAP + Analysis) kohdasta, napsauttamalla sivupaneelista.

![web](imagesh1/security_snapshot.PNG)

URL muuttui! Saadaan Download napista ladattua pcap tiedosto. <br> 
Nyt vaikuttaisi siltä, että url:issa näkyy hakemisto /data ja sen alla indeksi tai id /1. <br>
Task 2. vastaus on "data"

#### URL manipulointi
Vahva idea nousee 3. Taskista: "Are you able to get to other users' scans?"
Kysymys ohjaa IDOR haavoittuvuuteen päin. Vertaisille tiedoksi: <br>
(https://portswigger.net/web-security/access-control/idor) <br>
IDOR on pääsynhallinta haavoittuvuus jossa käyttäjän antamaa syötettä käytetään puhdistamatta palvelinpuolella. 


Tässä vaiheessa "/data" on varmaankin hakemisto tai tiedosto yms. olio. Jälkimmäinen numero viittaa sitten eri skannauksiin.

Taskin vastaus on kyllä.

#### PCAP
Vaihdoin numeron 0 ja siellä on muutama paketti enemmän kuin muissa snapshoteissa 0-5.
Avataan 0.pcap wiresharkilla. En ala sen enempää selittämään wiresharkin toimintaa, mutta pääpiirtein se näyttää verkkoliikennettä ja tarkemmin paketteja. Voidaan tarkastella mitä on liikkunut koneelle tai koneelta.

![web](imagesh1/WireShark.PNG)

Selaillessa paketteja huomaan ainakin TCP, HTTP ja FTP liikennettä. Ei tarvinnut kauaa selailla paketteja, kun FTP paketista löytyi käyttäjälle nathan salasana selkotekstinä.

![web](imagesh1/Creds.PNG)


Nathan on siis siirellyt jotain tiedostoja kohdekoneelta pois tai toisinpäin. Hänellä on siis oltava kelvollinen käyttäjä kohdekoneella ja meillä on nyt hänen tunnukset hallussa.

#### SSH
Koneella oli ssh portti auki, joten voitaisiin ottaa sellainen istunto ja katsoa mitä koneen sisällä tapahtuu.

![web](imagesh1/ssh.PNG)

Nyt ollaan sisällä. Katson mitä hakemistoja ja tiedostoja löydän komennolla:

```
ls
```

![web](imagesh1/ls.PNG)

Löysin user.txt nimisen tiedoston ja sen sisällön sain esille komennolla:

```
cat
```
Näyttää lipulta. Haisee lipulta. On lippu. Siinä oli user flag.

#### Root
Seuraavaksi halutaan saada kohdekoneelle root oikeudet. Kokeilen onko Nathanielilla sudo oikeudet.
```
sudo echo moi
```
![web](imagesh1/sudo.PNG)

Ja kiinni jäätiin! Nathaniel on nyt syntipukkina jos homma menee vihkoon, mutta nettikytät eivät ole kaukana kannoiltamme.
